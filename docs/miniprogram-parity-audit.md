## 2. Bug 清单

### MG-001 未完成训练被“我的”统计计入

- 页面：我的
- 现象：总组数与训练量直接统计全部 `sets`，包括 active 会话。
- 网页版：正式统计只计算 completed 会话。
- 小程序：sessions 数过滤 completed，但 sets/volume 未过滤。
- 原因：统计口径不一致。
- 严重等级：P1
- 修复：仅统计 completed 会话所属的组与训练量。
- 验证结果：Phase 2B 实况回归 PASS；active 会话及其组数、训练量不会进入我的、首页或历史正式统计，完成后会同步进入统计。

### MG-002 完成训练后计时器没有立即清理

- 页面：训练中/训练详情
- 现象：active 页面完成后重新加载为只读，但旧的一秒定时器继续 `setData` 到页面卸载。
- 网页版：完成后不再刷新计时。
- 小程序：仅 `onUnload` 清理，completed 分支未清理。
- 原因：计时器生命周期不完整。
- 严重等级：P1
- 修复：每次加载状态前统一清理旧计时器，completed 页面不再保留定时器。
- 验证结果：Phase 2B 实况回归 PASS；同一页面实例中 active 会话启动计时，完成后立即清理计时器。

### MG-003 运动数值字段允许负数和极端值

- 页面：羽毛球/游泳/网球新增与编辑、服务端数据 API
- 现象：除 RPE 外，时长、距离、圈数、卡路里、比分和技术数据缺少范围/整数校验；服务端只校验日期格式。
- 网页版：数字字段受表单语义约束。
- 小程序：异常值可进入 payload；绕过前端后服务端也会接受。
- 原因：前后端共用数据模型只有基础日期校验。
- 严重等级：P1（数据正确性）
- 修复：前端增加日期、正数、整数、比分、心率等校验；服务端增加同类兜底范围校验。
- 验证结果：Phase 2B 前端异常输入均被拦截且不发请求；服务端异常 payload 均返回 400，未知字段会被清洗。

### MG-004 首页力量统计包含 active 会话

- 页面：首页
- 现象：首页力量次数、累计次数、最近记录可能包含尚未完成的力量训练。
- 网页版：active 会话单独展示，不进入正式累计。
- 小程序：`listSessions({limit:100})` 未带 `status=completed`。
- 原因：查询条件遗漏。
- 严重等级：P1
- 修复：首页只查询 completed 力量会话。
- 验证结果：Phase 2B 带 active 数据实况回归 PASS；首页仅统计 completed 会话。

## 3. UI 差异

### MG-101 默认主题不一致

- 页面：全局、首页、训练、历史、我的、活动表单
- 现象：网页版 390×844 基准为深海军蓝页面；小程序大面积为浅灰背景白卡片。
- 网页版：`#081331` 一类深色背景与深色卡片层级。
- 小程序：全局 `#f2f4f7`，仅局部头部/卡片使用深色。
- 原因：小程序建立了独立浅色视觉方案。
- 严重等级：P2
- 修复：Phase 3 逐页按网页版色彩、层级、间距校正；不改网页。
- 验证结果：待 390×844 对照截图。

### MG-102 首页信息架构不一致

- 页面：首页
- 现象：小程序首页为四宫格运动入口；网页版首页重点展示今日训练状态和开始/休息操作。
- 网页版：今日训练卡 + 快捷开始 + 最近记录。
- 小程序：运动卡网格 + AI 卡 + 最近记录。
- 原因：页面产品结构未按 Golden Reference 对齐。
- 严重等级：P2
- 修复：Phase 3 采用最小改动重新编排现有能力。
- 验证结果：待回归。

### MG-103 游泳新增表单控件与顺序不一致

- 页面：游泳新增/编辑
- 现象：泳池长度使用自由数字输入；网页版使用“不限/25m/50m/其他”Picker；“其他”区顺序也不同。
- 网页版：时长/卡路里、距离与单位、泳池长度 Picker、圈数、泳姿、自动配速；其他区 RPE→场地→备注。
- 小程序：泳池长度数字输入；其他区场地→RPE→备注。
- 原因：控件和布局未逐项映射。
- 严重等级：P2

- 验证结果：待键盘遮挡、回填、空值测试。

### MG-104 Evan 与备注彩蛋

- 严重等级：P1（用户明确回归项）

- 验证结果：开发者工具可见；仍需真机遮挡检查。

## 5. 性能问题

### MG-301 底栏切换重建页面并重复请求

- 页面：四个主 Tab
- 现象：底栏使用 `wx.reLaunch`；网球页切首页实测约 1.1 秒，首页产生 6 个网络请求。
- 原因：页面实例被销毁重建；首页同时拉取用户、力量、三种运动和 AI 额度。
- 严重等级：P1
- 修复：四个主页面改为原生自定义 Tab；GET 使用按登录 token 隔离的 30 秒缓存，写入立即失效。
- 验证结果：连续首页↔训练切换 Network 为 0 个请求；底栏显示与选中态正常。

### MG-302 动作选择重复下载动作库

- 页面：训练中
- 现象：页面 `load()` 已取得动作库，打开选择器再次请求并重建相同数组。
- 原因：未复用页面已有数据。
- 严重等级：P1
- 修复：复用训练页已经加载的动作库。
- 验证结果：Phase 2B 实况回归 PASS；打开选择器不新增动作库请求。测试期间发现 `load()` 未保存动作库导致选择器为空，已做最小修复并纳入回归。

### MG-303 输入事件重复/大范围 setData

- 页面：游泳新增、动作库、训练动作选择
- 现象：游泳距离/时长一次输入触发两次 `setData`；动作搜索先写 query 再传完整 visible 数组。
- 原因：状态更新未合并，过滤逻辑在每个字符事件全量执行。
- 严重等级：P2
- 修复：游泳派生配速、动作库搜索和训练动作筛选均合并为单次状态更新，保持即时搜索体验。
- 验证结果：模块加载与 Phase 2B 交互回归 PASS。

### MG-304 历史长列表一次性加载和渲染

- 页面：历史时间线
- 现象：一次请求最多 500 条力量 + 1000 条活动，时间线模式一次渲染全部节点。
- 原因：缺少分段渲染；`onShow` 每次重算全部数据和日历。
- 严重等级：P1（超多历史数据场景）
- 修复：时间线首批仅渲染 80 条，到底后每批追加 80 条；完整历史仍保留。
- 验证结果：Phase 2B 导入 600 次力量训练、1800 组、900 次活动和 40 个休息日后，历史页共 1440 行；首批 80 条及后续每批 80 条追加、筛选、选日和月切换均 PASS。

### MG-305 “我的”每次进入拉取全量备份

- 页面：我的
- 现象：`onShow` 调 `/data/export` 并把所有云端记录传到小程序，仅为计算五个统计数字。
- 原因：缺少轻量统计接口/缓存。
- 严重等级：P1（数据增长后）
- 修复：全量备份加入短时缓存；任何数据写入立即失效；用户 token 参与缓存键。
- 验证结果：用户隔离、缓存命中、写后失效自动化 PASS；Phase 2B 超长数据下统计正确。
